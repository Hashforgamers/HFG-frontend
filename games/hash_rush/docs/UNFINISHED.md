# Unfinished / known gaps

**Assets**
- Characters, bosses, cannon, turret and barrel are real GLB models generated by `tools/build_assets.py`. They are
  stylised low-poly builds from rounded primitives — not sculpted, textured, artist-grade models.
- Environments are procedural geometry built in code (`rendering/Environment.ts`), not GLB kits.
- No textures beyond small canvas-generated ones; models are not Draco/Meshopt compressed (≈520 KB total, not worth it yet).
- The app thumbnail is a screenshot crop, not key art.

**Animation**
- Crowd animation is procedural in the vertex shader (idle, run, attack, fall, die, cheer). There is no separate
  "taking damage" clip for blue units (they flash/shrink), and enemy hit reaction is a white flash plus knock-back on death.
- Bosses are animated by rotating rigid parts in code — no skeletal rigs, no authored clips.

**Visuals**
- No heat-distortion pass in Volcanic Core (lava shader, embers and vents only). Bloom is on at medium/high; there are
  no real-time shadows (blob shadows instead).
- Explosions, trails and confetti are point sprites.

**Audio**
- Everything is synthesised with Web Audio: placeholder-grade SFX and a generated music loop per world.
  No recorded or licensed audio. Not auditioned on a device.

**Gameplay / balance**
- Tuned by scripted bots only (26/30 for the scripted bot at hand-off). Endless and the paid continue are not tuned at all.
- Skins are recolours of the same models, not new models. Pods and deploy effects keep the default cyan.
- Levels 6–30 are generated (seeded, validated); only 1–5 are handcrafted.
- Enemies ignore falling-platform holes.
- Agents do not avoid each other, so a large army overlaps when it bunches up.

**Platform**
- Tested on one Android phone only (see TESTING.md).
- WebGL context loss stops rendering until restore; resources are not rebuilt.
- WebGL2 is required; there is no WebGL1 fallback (a message is shown instead).

**Integration**
- Listed in the app with rewards live, but no server-side score validation exists (see INTEGRATION.md). In-app leaderboard screen has no
  data source inside the WebView. App-side analytics forwarding is Super Over-only.
